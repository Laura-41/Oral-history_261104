- `event_nodes.csv`：一级事件节点；
- `process_stages.csv`：二级过程阶段；
- `source_segments.csv`：全部原文片段；
- `source_attachments.csv`：原文与事件、阶段或文档之间的挂接；
- `entities.csv`：跨文档共享的实体总表；
- `entity_mentions.csv`：全部原文片段中的实体提及、字符偏移、来源和功能；
- `entity_aliases.csv`：实体的简称、历史名称、别称和转写变体；
- `entity_relations.csv`：任职、就读、隶属、地点层级和可能同一等关系；
- `event_times.csv`：事件的原文时间、规范起止、精度、确定性和来源；
- `time_expressions.csv`：全部原文中的明确年月日及其规范值、字符偏移和来源；录音时间戳不进入本表；
- `coverage_audit.csv`：原文覆盖率审计。

## 四 人工确认的最低标准

- 每个一级事件都有事件名称、六类事件之一、核心过程、参与者、环境和原文证据；
- 只有确实需要展开的长事件才建立二级阶段；
- 一级事件之间只建立历史时间顺承的 `NEXT`；
- 采访者提问、编校注释、时间码和无关信息仍保存在原文层；
- 每一条原文片段至少挂接事件、阶段或文档中的一个；
- `coverage_rate` 必须保持为 `1.0000`。
- 每个实体提及的 `start_offset/end_offset` 必须精确返回原文；
- 同一实体跨文档使用同一 `entity_id`；
- 人物小传、脚注和采访者提问中的实体不能冒充受访者事件论元；
- 每个一级事件都有 `EventTime`，不确定时间必须显式记录精度和确定性；
- 每条全文日期提及进入 `TimeExpression`，并保留原文偏移和来源；录音时间戳不得误作历史时间；
- `review_status` 表示是否人工核验，`authority_status` 表示现实指称是否能够规范确定，二者不得混用；
- 每份访谈继续保留自己的 `NEXT`，不得用人物生平链覆盖文档事件链；
- 同一人物的多次访谈通过 `INTERVIEW_OF` 汇聚到同一个人物核心；
- 人物经历使用 `LifeEpisode`，按真实历史时间建立 `BIOGRAPHICAL_NEXT`；同一经历在多份访谈中重复出现时，一个 `LifeEpisode` 可以连接多个来源事件；
- “受访者亲历／参与的经历”和“受访者讲述的集体历史背景”必须区分，后者使用 `NARRATED_CONTEXT`；
- 不同人物之间的综合时间轴仍由规范时间动态生成，不建立跨人物强制顺承链。
